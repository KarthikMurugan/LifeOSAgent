My next milestone was a calendar tool. I checked the actual tool request, the returned data and the final answer, rather than assuming a plausible response proved the agent had retrieved information.

080–100 seconds | 05-state.png | Understanding state and memory
I asked for explanations as I built. I learned to distinguish graph state, saved checkpoints and conversation history. The early exercise used temporary planner storage; the final application uses separate persistent SQLite stores.
Exact source turn: 01a1243d-ad49-76e2-ae7b-e37b437ad6c6

100–120 seconds | 06-scheduler.png | Separating reasoning from scheduling
I learned why the model should not invent calendar times. The LangGraph workflow gathers context, detects conflicts, schedules, validates and summarizes. Python preserves commitments and defers tasks that cannot fit.
Exact source turn: 01a1243e-be6f-7c62-9075-3c4d31c5de5a

120–140 seconds | 07-integration.png | Connecting the complete application
I connected the planning button and Copilot to FastAPI. The backend returns the model’s reply and the scheduler’s structured plan. The interface renders those blocks directly, preserving the existing design.
Exact source turn: 01a124a7-6933-7952-a3c8-a32700782216

140–160 seconds | 08-validation.png | Iterating without breaking functionality
Finally, I refined the layout so Copilot and a narrower calendar sit beside each other. I verified backend tests, browser interactions and live Ollama planning. AI helped me build and debug, while I reviewed the behavior and learned the code.
Exact source turn: 01a124f0-015e-7301-bf7f-28cec4b6c9d9

160–240 seconds | Live product demo (or image 09 if the application is unavailable)
Show Today, click Plan my day, explain the resulting calendar, open Copilot, ask a follow-up, then complete a task and replan. Start model processing early; local inference can take time. Explain that tasks and events use seeded data and no external calendar is modified.

240–300 seconds | Code walkthrough
Show dist/api.js for frontend requests, backend/main.py for FastAPI validation and endpoints, backend/agent_service.py for ChatOllama/create_agent/four tools, and backend/planner.py for StateGraph and scheduling rules. End with the distinction: the model selects tools and explains, while Python computes the schedule.
